# x402: the agent pays HTTP APIs, the vault signs

An API that answers `402 Payment Required` (x402, `exact` scheme) names an amount of USDC and a payee.
With contract version 3, the agent asks the vault, and the vault signs an EIP-3009
`transferWithAuthorization` of USDC from **its own EVM address**, through NEAR Chain Signatures. The
agent holds no EVM key, and the vault pays no gas: the API's facilitator submits the authorization.

The same rules as every other payment apply on chain, in `pay_x402`:
- the agent key and its policy (enabled, unexpired, version);
- the payee must be an allowed recipient on that chain;
- the per-payment limit, and the agent's and the vault's daily limits;
- a payment id pays once.

Over the per-payment limit it is refused: x402 has no approval path.

The vault fixes every signed field itself:
- `from`: the vault's address, set by the owner;
- `to`: the allowed payee;
- `value`: the amount;
- `validBefore`: the payment's expiry;
- `nonce`: the payment's own hash.

The callback recovers the MPC signature with `ecrecover` and keeps the authorization only if it
recovers to the vault's address. Otherwise the payment rolls back.

## What is checked so far

- **Contract unit tests** (`contracts/near/styx-vault/src/tests.rs`, the `x402_` tests): the EIP-712
  digest matches an independent computation; the signature recovers to the vault's address; a
  signature from any other key, or a failed signer, rolls everything back; the limits, the recipient
  allowlist and the owner-only setters hold.
- **Base Sepolia USDC** (`0x036CbD53842c5426634e7929541eC2318f3dCF7e`) reports name `USDC`, version
  `2`, domain separator `0x71f17a3b…9818` and transfer type hash `0x7c7c6cdb…2267`. These are the values the
  vault hashes.
- **MCP** (`mcp-server/tests/test_vault.py`): `styx_pay_x402` against a fake 402 API with a scripted
  vault sends a correct `X-PAYMENT` header and returns the resource.

Not yet run on testnet: everything below.

## Base Sepolia run

1. Build the vault (version 3) and redeploy the factory, which embeds the vault code at build time:
   `contracts/near/build.sh`, then deploy `styx-factory` again. Existing vaults stay on version 2.
2. Create a new vault from the console. Then, as the owner:
   - `set_evm_chain(84532, {token: "0x036cbd53842c5426634e7929541ec2318f3dcf7e", ...gas caps, enabled: true})`;
   - `set_evm_address(<scripts/near/derived_address.sh <vault>>)`;
   - `set_x402_domain(84532, "USDC", "2")`;
   - `set_evm_recipient(84532, <the API's payTo>, true)`.
3. Fund the vault's EVM address with Base Sepolia USDC (https://faucet.circle.com). It needs no ETH.
4. Point the agent at an x402 endpoint on base-sepolia (any API using the x402 `exact` scheme with
   the public facilitator), and ask: "fetch <url> with styx_pay_x402".
5. Expect: `status: paid`, the API's answer, and a `settlement` with the Base Sepolia transaction.
   Check the vault's USDC balance went down by exactly the amount, and record the transactions in
   `TESTNET_RUN.md`.
